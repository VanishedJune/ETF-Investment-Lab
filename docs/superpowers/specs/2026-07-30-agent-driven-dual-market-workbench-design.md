# 双市场周线投资研究工作台设计规格

**批准日期：** 2026-07-30  
**目标市场：** 创业板指数 `399006`、纳斯达克100指数 `NDX`

## 1. 产品范围

前端从七个路由收敛为一个研究工作台，只展示两个直接指数。旧数据库表和历史数据不物理删除，但不再提供科创50、计划、模拟账户、真实账户、历史情景和数据金库的导航入口。

单页包含：

1. 指数日/周/月行情，默认周线；
2. 周成交量、DIF、DEA、MACD、RSI、均线和估值；
3. 当前市场状态、目标仓位、分批操作建议；
4. 基金/ETF整数比例建议；
5. Agent离线递进迭代曲线和模型指标；
6. 可持久化的投资日历，可记录真实买卖份额。

系统不连接券商、不自动交易、不包含资金收益模拟，结论仅供研究。

## 2. 周线数据

正式模型只读取已经结束的完整周。未结束周可以显示，但必须标为临时数据，不能进入正式建议和迭代。

创业板周成交量优先尝试上游周线接口。上游数据必须通过覆盖范围、非空、非异常零值、日期对齐和单位一致性检查。检查失败时，从本地日线按ISO周求和：

```text
周成交量 = 当周全部有效日成交量之和
```

每根周线记录保留来源。日线聚合来源使用 `AGGREGATED_DAILY_VOLUME`。不得用0、前值或插值制造成交量。

`NDX`若不存在直接指数的可靠原生成交量，不使用ETF成交量冒充；模型把成交量维度视为缺失并降低置信度。

## 3. 指标语义

周线MACD采用12/26/9初始参数：

```text
DIF = EMA12 - EMA26
DEA = DIF的9周EMA
MACD柱 = 2 × (DIF - DEA)
```

为兼容需求中的命名而不制造重复指标：

```text
DIP = DIF（快速趋势线）
EDA = DEA（慢速信号线）
```

页面显示为 `DIP / DIF`、`EDA / DEA`。黄金点是DIP向上穿越EDA并获得趋势/估值/价格确认，黑点是DIP向下穿越EDA并获得相应确认；强度分弱、普通、强、极强四档。

## 4. 双市场模型

两个市场拥有独立参数、版本和迭代历史。

创业板初始维度权重：

```text
估值20、EDA20、DIP20、黄金点/黑点15、价格趋势15、市场环境10
```

纳斯达克100初始维度权重：

```text
估值15、EDA22、DIP22、黄金点/黑点12、价格趋势19、市场环境10
```

每个维度输出 `-100..100`，权重总和始终为100。估值限制仓位上下限但不能独立触发满仓或清仓。

## 5. 动态仓位和分批执行

模型输出当前标准化仓位、目标仓位、建议变化、第一批和条件批次。标准化满仓为100份，不进行资金或收益模拟。

减仓规则：

- 不超过20个百分点：1至2批；
- 20至50个百分点：40%/35%/25%；
- 超过50个百分点：40%/30%/20%/10%。

加仓规则：

- 默认30%/30%/25%/15%；
- 低估但趋势未确认时最多试探增加10个百分点；
- 后续批次必须等待周线确认。

禁止默认一次卖出90%。建议变化小于5个百分点时不执行。普通状态保留至少10%底仓。

## 6. 基金与ETF比例

比例只能三选一，不允许连续小数比例：

| 市场状态 | 基金:ETF |
|---|---:|
| 强势/牛市 | 7:3 |
| 温和上涨/震荡偏强 | 6:4 |
| 弱势/熊市/冲突 | 5:5 |

实际仓位使用最大余数法分配为整数，基金仓位加ETF仓位必须等于目标仓位。熊市风险通过降低总目标仓位控制，不增加第四种比例。

## 7. Agent递进迭代

训练和模拟不在Web后台执行。Codex等Agent显式运行本地离线脚本，Web后端只读取持久化结果。

每个市场在2026-07-30基线交付前完成100次递进迭代。候选截断点使用固定随机种子分层选择后按时间升序排列；下一截断点必须晚于上一轮10/15/20交易日结果全部揭晓的日期。

每轮执行：

1. 用当前模型和截止日之前的完整周线生成建议；
2. 隐藏截止日之后的数据；
3. 记录预测操作日期、方向、目标仓位和批次；
4. 揭晓后续10/15/20个交易日；
5. 计算方向、概率误差和有符号偏离交易日；
6. 使用本轮结果对下一版权重、阈值和置信度做有界更新；
7. 保存模型版本和数据哈希。

因此 `M2`必须包含第1轮反馈，`M100`必须包含前99轮反馈。单次维度权重调整不超过2个百分点。

2026-07-30之后，每个市场每月新增两次已完成迭代。尚未拥有完整未来观察窗的信号标为 `pending`，不能计入已完成次数。

## 8. Agent可发现协议

项目根目录提供 `AGENTS.md`，并提供：

```text
docs/AGENT_MODEL_ITERATION.md
config/agent_iteration_policy.json
scripts/agent-model-iteration.ps1
data/model_iterations/399006/
data/model_iterations/NDX/
```

未来Agent必须先运行状态检查，再运行到期迭代。所有结果可从固定随机种子、源数据哈希和前一模型版本重复生成。

## 9. 投资日历

投资日历持久化到SQLite，字段为指数、产品名称、产品代码、产品类型（基金/ETF）、买卖方向、日期、份额、可选成交价格和备注。支持新增、修改、删除、月历/列表展示。

日历只计算净份额，不建立现金账户或收益模拟。

## 10. 验收

- 只存在一个可导航页面和两个指数；
- 创业板周/月成交量无历史空洞且来源可审计；
- 未完成周不进入模型；
- 两个市场分别存在100条递进迭代记录和M100；
- 第N轮的源数据最大日期不晚于其截断日期；
- 三档基金/ETF比例及实际分配均为整数；
- 投资日历重启后不丢失；
- 后端测试、前端构建和Playwright验收全部通过。
